# LowCode-AIOps: Гибридная система выявления и интерпретации аномалий в системных логах

Прикладная реализация гибридного конвейера автоматического обнаружения инцидентов и проведения корневого анализа причин (Root Cause Analysis, RCA) в системных журналах без необходимости предварительной ручной разметки данных.

Система объединяет скорость **семантических энкодеров (Sentence-BERT)**, аналитическую мощность **генеративных больших языковых моделей (Qwen2.5)** и доступность **Low-code оркестрации (n8n)**.

---

## 💡 Основная идея и Архитектура

Традиционные системы AIOps требуют сложных обучающих выборок, а классические LLM слишком медленны и ресурсоемки для сплошного потокового анализа логов. 

Данное решение использует **двухуровневый гибридный фильтр (Router Pattern)**:

```
[Поток логов] 
     │
     ▼
┌─────────────────────────────────────────────────────────┐
│ Уровень 1: Оперативный семантический энкодер (Fast)      │
│ (Sentence-BERT: all-MiniLM-L6-v2 + Cosine Similarity)   │
└────────────────────────────┬────────────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            │                                 │
 [Similarity < 0.25]               [Similarity >= 0.25]
            │                                 │
            ▼                                 ▼
   ┌─────────────────┐             ┌─────────────────────────────┐
   │ STATUS: NORMAL  │             │ Уровень 2: Генеративная LLM │
   │ (Отфильтровано  │             │ (Qwen2.5 7B via Ollama)     │
   │  за < 0.01 сек) │             └──────────────┬──────────────┘
   └─────────────────┘                            │
                                                  ▼
                                       ┌──────────────────────┐
                                       │ STATUS: ANOMALY      │
                                       │ + Root Cause Analysis│
                                       │   (Причина сбоя)     │
                                       └──────────────────────┘
```

1. **Уровень 1 (Fast Semantic Encoder):** Каждая поступающая строка лога переводится в семантический вектор с помощью `all-MiniLM-L6-v2`. Вычисляется косинусное сходство с эталонными векторами аномалий. Если лог с высокой вероятностью рутинный (`similarity < 0.25`), он отсекается за миллисекунды.
2. **Уровень 2 (Generative LLM + RCA):** Подозрительные логи перенаправляются в локальную модель `Qwen2.5 (7B)`. Модель проводит глубокий семантический анализ, подтверждает аномалию и генерирует текстовое объяснение первопричины сбоя (Root Cause Analysis) в формате JSON.
3. **Low-Code Оркестрация (n8n):** Весь пайплайн собран в визуальном конструкторе n8n, что позволяет DevOps/SRE-инженерам внедрять и адаптировать систему без написания серверного кода.

## ⚠️ Проблемы и ограничения системы (Known Issues & Limitations)

Несмотря на высокие показатели на явных текстовых ошибках, проведенный критический анализ выявил следующие фундаментальные ограничения текущей версии:

### 1. Неприменимость построчного анализа к структурным/последовательностным аномалиям (Проблема HDFS)
* **Суть проблемы:** В датасетах вроде HDFS аномалия заключается не в тексте отдельной строки, а в нарушении цепочки событий (например, обрыв передачи блока `BlockId`). Отдельные строки аномального блока содержат стандартный текст `INFO: Receiving block...`.
* **Последствие:** Построчный семантический энкодер и LLM классифицируют одиночные строки как `normal`, выдавая критически низкую полноту (**Recall = 0.0227** на HDFS).
* **Требуемое решение:** Необходим переход от построчного анализа к **агрегации логов по сессиям/контекстным окнам (BlockId Batching)** перед подачей на Уровень 1.

### 2. Слепота к частотным аномалиям (Time-Series / Rate-based attacks)
* **Суть проблемы:** Система не способна выявлять аномалии, основанные на частоте событий (DDoS-атаки, Brute-force авторизации, каскадные повторы).
* **Причина:** Одиночная строка `Failed password for user` не является аномалией. Аномалией являются 100 таких строк за 2 секунды. Построчный анализ без временного окна (Time-Window) принципиально не видит частотный контекст.

### 3. Зависимость от локальных вычислительных ресурсов (VRAM / RAM)
* **Суть проблемы:** Генерация объяснений (RCA) на базе `Qwen2.5 (7B)` через Ollama требует наличия видеокарты с объемом VRAM от 8 ГБ (или мощного CPU), что может создавать задержки (Latency до 1-2 сек на лог) при массовых всплесках аномалий (Alert Storms).

### 4. Хрупкость JSON-форматирования LLM
* **Суть проблемы:** Несмотря на фрэймворк Ollama и флаг `"format": "json"`, локальные малые LLM в редких случаях могут генерировать некорректный JSON (например, при наличии незаэкранированных кавычек в тексте лога), что приводит к срыву парсинга на уровне n8n.

## 🛠️ Стек технологий

* **Low-code оркестратор:** [n8n](https://n8n.io/)
* **Fast Encoder:** `sentence-transformers/all-MiniLM-L6-v2` (PyTorch / HuggingFace)
* **LLM Engine:** [Ollama](https://ollama.com/) (`qwen2.5:7b`)
* **Окружение:** Docker / Docker Compose
* **Язык скриптов валидации:** Python 3.10+ (`pandas`, `requests`, `scikit-learn`)
